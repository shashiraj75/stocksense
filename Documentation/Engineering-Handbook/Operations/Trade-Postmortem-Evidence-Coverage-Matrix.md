# Trade Postmortem — Evidence Coverage Matrix

Sprint 3b (feature/postmortem-explainability-phase). Human-readable companion
to `backend/tests/unit/postmortem_evidence_coverage_matrix.json` (the
machine-readable source of truth, keyed `{"entries": [...]}`) and
`backend/tests/unit/test_postmortem_evidence_coverage_matrix.py` (the
introspection test that fails this document out of date).

One row per unique (report_section, internal_factor, rule_id) combination
this codebase's postmortem rule/claim-building code can actually produce,
as of this sprint's inventory of:

- `backend/services/postmortem/evidence_attribution.py` — `RULE_REGISTRY`
  entries `SIG_ENTRY_FACT_001`, `THESIS_DIRECTION_PATH_001`,
  `CONTRIBUTOR_POSITION_MANAGEMENT_001`, `EXIT_MECHANISM_001`,
  `CONTRIBUTOR_UNACQUIRED_EVIDENCE_001`,
  `CONTRA_ENTRY_SIGNAL_DISAGREEMENT_001`, `CONTRA_MOMENTUM_VS_RANGE_001`,
  `CONTRA_REQUIRES_PRICE_PATH_001`, `PRIMARY_CONTRIBUTOR_SELECTION_001`.
- `backend/services/postmortem/governed_price_path_claims.py` — the current
  (1.2.0) `governed_price_path` report_section: `GOVERNED_TARGET_TOUCH`,
  `GOVERNED_STOP_TOUCH`, `GOVERNED_TOUCH_ORDER`.
- `backend/services/postmortem/price_path_claims.py` — the frozen legacy
  (1.1.0) `price_path` report_section: `MFE`, `MAE`, `TOUCH_ORDER`. This
  module also registers rule_ids used as limitation/reason annotations
  rather than independent claim-producing factors (`PRICE_PATH_WINDOW`,
  `TARGET_TOUCH`, `STOP_TOUCH`, `SAME_BAR_AMBIGUITY`,
  `ENTRY_BOUNDARY_AMBIGUITY`, `EXIT_BOUNDARY_AMBIGUITY`,
  `GAP_THROUGH_LEVEL`, `MFE_GIVEBACK`, `CAPTURED_MFE`,
  `PRICE_BASIS_COMPATIBILITY`, `MISSING_LEVEL_HISTORY`) — those are
  intentionally not separate rows here.
- `backend/services/postmortem/exit_evidence.py` — the `exit_evidence`
  report_section, built inline (no `register_rule` entries):
  `EXIT_EVIDENCE_MISSING_V1`, `EXIT_MECHANISM_V1`, `EXIT_EXECUTION_V1`,
  `EXIT_MANAGEMENT_LEVELS_V1`, `EXIT_TRIGGER_TIMING_V1`.

## Column definitions

- **status**: COMPLETE (evidence is captured for essentially all trades),
  PARTIAL (captured for some trades, not others, depending on data-capture
  paths this sprint did not modify), UNAVAILABLE (this codebase does not
  yet acquire the evidence at all).
- **remediation_category**: A. AVAILABLE_NOW (frontend-only fix — reuse
  existing governed data, this sprint's actual deliverable), B.
  EXISTING_DATA_NOT_PROPAGATED (a backend field exists but isn't always
  populated by every Buy call site), C. REQUIRES_SERVER_VERIFICATION (needs
  durable server-side verification against price bars/timing), D.
  REQUIRES_NEW_ACQUISITION (needs a wholly new evidence-acquisition
  pipeline this codebase does not have), E. LEGACY_NOT_RECOVERABLE (frozen
  1.1.0 report path, or a legacy trade missing an exit snapshot — cannot be
  retroactively upgraded without breaking the "no dual semantic authority"
  gate), F. DELIBERATELY_NOT_ASSESSABLE (should stay unassessable even
  after future phases — see the roadmap doc's per-factor rationale).

(`PRICE_PATH_WINDOW`, `TARGET_TOUCH`, `STOP_TOUCH`, `SAME_BAR_AMBIGUITY`,
`ENTRY_BOUNDARY_AMBIGUITY`, `EXIT_BOUNDARY_AMBIGUITY`, `GAP_THROUGH_LEVEL`,
`MFE_GIVEBACK`, `CAPTURED_MFE`, `PRICE_BASIS_COMPATIBILITY`,

are used only as limitation/reason annotations on the legacy MFE/MAE/
TOUCH_ORDER claims, never as independent claim-producing factors — see the
"legacy_..." rows below.

## How this matrix stays honest

`backend/tests/unit/test_postmortem_evidence_coverage_matrix.py`
introspects `evidence.RULE_REGISTRY` and calls the real claim-building
functions in `evidence_attribution.py` and `exit_evidence.py` with
representative fixtures, collects every (report_section, factor) pair
those functions actually emit, and fails if any pair is missing from
`postmortem_evidence_coverage_matrix.json`. If a future sprint adds a new
rule or factor, that test fails until this document and the JSON file are
updated together — this matrix cannot silently go stale.
